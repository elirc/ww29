# Codebase map

The open route calls [markNotificationOpenedForSession](../src/services/notificationService.ts) after session and request handling. The service requires `notifications:open:own`, finds notification detail with deliveries, returns 404 for a missing record or a viewer outside the recipient boundary, and rejects unless at least one delivery is SENT. It then calls `markDeliveryOpened`, updates the notification opened timestamp, recomputes notification status from delivery statuses, recomputes batch status from notification statuses, and writes `notifications.opened` audit data.

The permission matrix is centralized in [permissions.ts](../src/lib/auth/permissions.ts): ADMIN and OPERATOR can view any, while VIEWER can view own. Repositories in `src/repositories` own Prisma writes and reads; the service owns sequencing and policy. The [runtime lab](../tests/runtime-notification-open-lab.test.mjs) loads both production service and permission module. It supplies explicit detail and status repository doubles so call order is visible. A reviewer should trace three boundaries separately: identity and authorization, lifecycle state (`SENT`), and aggregate refresh. A route-only test can miss service callers, while a repository-only test can miss wrong-recipient denial. The current scope deliberately stops before worker delivery and real transaction behavior.
