# WW29 notification-open CRUD course

This course follows `markNotificationOpenedForSession` in [notificationService.ts](../src/services/notificationService.ts). The service is responsible for authorization, sent-delivery eligibility, delivery mutation, notification and batch status refresh, and audit logging. The staged improvement is an executable service lab, not a production patch: [runtime-notification-open-lab.test.mjs](../tests/runtime-notification-open-lab.test.mjs) loads the real service and the real permission matrix, error class and status derivation functions, while injecting repository and database boundaries.

Six cases pass. A viewer cannot open another recipient's notification and causes no writes. An owner cannot open a notification with no SENT delivery. A sent owner open updates the delivery, notification status, batch status, and audit. An admin can open another recipient's sent notification through the same path. Run the command in VERIFICATION.md from the project directory. The test does not claim live Prisma transactionality, route schema coverage, or delivery worker behavior. Chapters map the service and repositories, explain ownership and state transitions, show the before/after learning addition, provide debugging traces, and separate exercises from answers. Use the limits when reviewing any follow-up to make opening transactional or idempotent.
Two additional cases exercise actual PARTIAL_FAILURE derivation for mixed statuses and an aggregate update failure after delivery/opened-at writes. The latter demonstrates partial progress: this open operation has no encompassing transaction.
