# Worked runtime addition

The existing project tests use Vitest mocks for one foreign-detail case and one unsent transition. The staged addition executes the real service function and production permission matrix in a VM. Before the addition, a test could prove a mock was called without proving the service orders delivery mutation, opened timestamp, status refresh, and audit. After the addition, a sent owner fixture records that complete path and an admin fixture proves the any-recipient permission flows into the same transition.

The test's before/after learning code is the fixture boundary, not a copied business predicate. Before: the scenario is described by mocked module calls. After: `findNotificationDetail` returns a realistic notification with deliveries, `markDeliveryOpened` and status repositories record writes, and the actual service decides whether each call occurs. The foreign viewer and unsent cases assert zero writes, while the sent owner asserts the exact sequence. Read [runtime-notification-open-lab.test.mjs](../tests/runtime-notification-open-lab.test.mjs) beside [permissions.ts](../src/lib/auth/permissions.ts). No production source snapshot is needed because this is a teaching lab. The design still needs a provider-backed decision about transaction boundaries and repeated-open semantics.
