# Testing and debugging

When a foreign viewer test fails, inspect the detail lookup, role permission, and recipient comparison before any delivery call. A 403 would reveal an authorization policy mismatch; the intended data-isolation result is 404. When an unsent test fails, inspect the `SENT` filter. It must reject before `markDeliveryOpened`, timestamp update, status refresh, and audit. For a successful case, the expected call order is delivery open, notification opened timestamp, notification status update, batch status update, audit.

The lab loads production TypeScript and production permission logic, but stubs repositories and Prisma. Run `node --experimental-vm-modules --test tests/runtime-notification-open-lab.test.mjs` and read [the captured log](evidence/crud-b06-astra-runtime.log). The test asserts status and message fields rather than cross-VM `instanceof`. It does not execute Next route schemas, a real database transaction, or worker delivery. A useful follow-up should inject a failure during batch refresh and verify whether the delivery and opened timestamp roll back or require an outbox. Another should call the operation twice and define whether the second call is a no-op, a conflict, or another audit. Debug those policies from source rather than weakening assertions to make a fake pass.
